# mech-review-ts/cap: a TS PR over `max-mutants` runs its riskiest changed lines, the same pick every run, R3 partial; under the cap every changed line runs as before

- story: As a TypeScript repo owner whose PR makes more mutants than the cap, R3 runs Stryker on the riskiest changed lines only (branch conditions, then returns and boolean literals, then arithmetic, then the rest, strings last), picks the same lines on every run, reads `partial (tested/total)` instead of `pass`, and a PR under the cap runs every changed line exactly as before.
- covers: #63 63.1 (over the cap: capped at max-mutants, riskiest first in #26's order, the same pick on every run and after a shuffled listing; `partial (tested/total)`, `N past the cap (max-mutants M): untested`, never `pass`; a survivor in the pick is MISSED, one past the cap is not; shards split the pick by file, merge `partial (5/14)`; a JSON repo config's `excludedMutations` is honoured); 63.2 (under the cap, 14 in 14 and the default 40: every changed line runs, `14/14 tested`, R3 pass, no cap note); 63.4 (under the cap the Stryker argv is the one before #63: one `--mutate` range per changed run of lines, `--reporters json --allowConsoleColors false --timeoutMS 120000`; MISSED entry text; `baseline` one shard per changed file; a config that is code gets no cap and the note says `max-mutants not applied`)
