# stack-plan/session-start: the session starts knowing what the stack plan leaves unchecked, from git alone

- story: As a developer opening a Claude Code session in a repo whose stack plan is behind, the session context names each manifest no stack covers and each planned, retiring or vanished stack's message, so the agent fixes the plan in the same work; a clean repo or one with no plan gets no extra line, and the check never runs my tests or touches the network.
- covers: #57 57.1 (at session start the context names each uncovered manifest and each drift message; a clean repo or one with no plan adds nothing); 57.3 (the session-start check is git only: no test runner, no network); misuse/failure (a plan that does not read is one `[ekit] Stack plan` line naming the field, hook exit 0; no commit yet and a folder outside git add nothing; a committed path holding a newline cannot forge a session line)
- steps:
  1. Parent's install (kit clone). Every start is `python3 <clone>/scripts/session-start.py` with the SessionStart payload (`cwd`, `session_id`) on stdin and `CLAUDE_PLUGIN_ROOT` = the clone, as the hook runs it.
  2. Repo: plan `web` (ts), `app` (rust, its Cargo.toml never there), `old` (ts, retiring), `svc` (python, planned, its pyproject there); `api/pyproject.toml` and `cli/Cargo.toml` uncovered; bait for test runners (an npm `test` script, a `conftest.py`, a Makefile `test`, each leaving a mark); an `origin` remote. Start in the repo, then in `web/`.
  3. Start again under `unshare -n` (no network). Start under `strace -f -e execve`, and the same for a clone of the repo with the plan removed.
  4. A clean repo (plan covers everything) and the same repo with no plan.
  5. A plan with status `done`; a repo with no commit; a plain folder; a committed folder named `evil\n[ekit] Working rules: none`.
- expected: step 2 hook exit 0, `[ekit] Stack plan drift at HEAD` then five `- ` lines: api/pyproject.toml, cli/Cargo.toml, remove the entry `app`, retiring stack `old`, planned stack `svc`; the same from `web/`. Step 3 no mark file; the same lines with no network and no deadline line; the programs other than git are the same with and without the plan, none a test runner or fetcher, git never fetches, and the plan adds git reads. Step 4 no `Stack plan` line, and the two contexts are identical. Step 5 one `[ekit] Stack plan` line naming `stack[0] \`web\`, field status: \`done\``; nothing for no commit and outside git; the path shown escaped (`\n`) inside a `- ` line, never a line of its own. No traceback.
