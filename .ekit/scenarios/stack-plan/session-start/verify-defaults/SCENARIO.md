# stack-plan/session-start/verify-defaults: the session starts with each stack's build, lint and test commands declared, as CI runs them

- story: As a developer opening a Claude Code session in a repo with one or several projects, the session already holds each stack's build, lint and test commands as its verify commands, each run in its own folder and each shown with the `task-verify.py ... run` line that records it, so I do not have to declare them; a step my adapter names no command for is named once, and when the hook cannot tell which stacks there are it declares nothing and says why in one line.
- covers: #61 61.1 (a plan of two current stacks: each one's build, lint and test, as `cd <folder> && <cmd>`; a planned stack with no manifest declares none; install never); 61.2 (no plan: the one stack `auto` finds gives its commands, at the root a plain command, a repo adapter file included; several projects or none declare nothing, one line why); 61.3 (the commands CI runs: a built-in's test as R1/R4 run it, jest when the project lists only jest, vitest when it lists vitest, `cargo test`, `python3 -m pytest`; a retiring stack and a planned one whose manifest is there); 61.4 (a step with no command named once per stack: a built-in's build and lint, `lint = ""`, no `[commands]` table); misuse/failure (a plan that does not read, an adapter file that is not TOML, a command holding a run of spaces, no commit, outside git, no `session_id`: one line, hook exit 0, never a guess)
- steps:
  1. Parent's install (kit clone). Every start fires the clone's `hooks/hooks.json` SessionStart command with the payload (`cwd`, `session_id`) on stdin and `CLAUDE_PLUGIN_ROOT` = the clone; what was declared is read back with `task-verify.py check <session>`.
  2. Plan: `web` (adapter file `.ekit/adapters/web.toml`, ekit's ts.toml with `build = "npm run build"`, `lint = "npx eslint ."`; package.json lists only jest), `api` (python), both current; `mob` (rust, planned, no Cargo.toml). Start in the repo, then in `web/`; then with an unplanned `cli/Cargo.toml` added.
  3. Plan: `old` (ts, retiring, jest only), `new` (ts, jest and vitest), `svc` (python, planned, its pyproject there), `core` (rust).
  4. No plan: a root package.json listing jest; a root `build.gradle.kts` with `.ekit/adapters/tool.toml` (commands install, build, `lint = ""`, test); the same adapter with no `[commands]`; two projects; no project.
  5. Misuse: plan status `done`; adapter file not TOML; `test = "grep  -q ok src.kt"` (two spaces); no commit; a plain folder; a payload with no `session_id`.
- expected: step 2 declared exactly `cd api && python3 -m pytest`, `cd web && node_modules/.bin/jest`, `cd web && npm run build`, `cd web && npx eslint .`, one context line each naming the step and stack, ending with `python3 <clone>/scripts/task-verify.py --repo <repo> run -- '<cmd>'`; no `npm ci`, nothing for `mob`; one line naming api's missing build and lint; the same from `web/` and beside the drift line. Step 3 `cd core && cargo test`, `cd new && node_modules/.bin/vitest run`, `cd old && node_modules/.bin/jest`, `cd svc && python3 -m pytest`, each stack's build and lint named once. Step 4 `node_modules/.bin/jest` (plain, run line `run -- node_modules/.bin/jest`); `grep -q ok src.kt` and `test -f build.gradle.kts`, lint named once, install never; no `[commands]`: nothing, one line naming build, lint and test; several and none: nothing declared, one `none declared: several projects` (naming both) / `none declared: no project` line. Step 5 nothing declared and one `Verify defaults` line each (bad plan naming the field, the adapter file named); the spaces case declares the build only and one line says test was not declared for its whitespace. Hook exit 0 and no traceback throughout.
